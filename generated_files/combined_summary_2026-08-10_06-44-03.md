### System Design and Security Fundamentals

Robust system design and strong security practices are crucial in the modern tech landscape.
*   **Redis Data Structures:** Engineers should be familiar with various Redis data structures for different applications:
    *   **Strings:** Counters, session tokens, cached payloads.
    *   **Hashes:** Storing object fields, allowing partial updates.
    *   **Lists:** Ordered sequences for queues, feeds, and recent items (fast push/pop).
    *   **Sets:** Unique members for tagging, follower overlap, and deduplication.
    *   **Sorted Sets:** Ranking members by score for leaderboards, priority queues, and range queries. Geospatial indexing uses Sorted Sets with geohash scores.
    *   **Streams:** Append-only logs with consumer groups for message tracking.
    *   **JSON:** Storing nested documents with JSONPath for deep field updates.
    *   **Vector Set:** For approximate nearest-neighbor search over embeddings, used in RAG pipelines.
    *   **Time Series:** Storing timestamped samples with built-in retention and downsampling for metrics, telemetry, and IoT data.
*   **API Security Best Practices:** Critical for preventing breaches, which often stem from broken authorization, leaked secrets, or missing rate limits. Key practices include:
    *   Using modern OAuth/OIDC + MFA (PKCE, short-lived tokens, step-up MFA).
    *   Enforcing fine-grained authorization (object, function, field-level permissions).
    *   Minimizing scopes and data returned.
    *   Encrypting every hop (TLS, mTLS).
    *   Protecting secrets and keys (HSM-backed vaults, rotation).
    *   Validating requests with schemas.
    *   Implementing rate limits and resource caps.
    *   Defending sensitive business flows (anti-bot, idempotency, step-up auth).
    *   Controlling outbound and third-party calls.
    *   Hardening configuration and error handling.
    *   Inventorying APIs and versions.
    *   Logging, detecting, and responding to anomalies.
    *   Webhooks, which enhance product engagement and integrated workflows, can be complex to manage in-house; services like Svix offer comprehensive handling of retries, idempotency, and security.

*   **Continuous Integration (CI), Continuous Delivery (CD), vs. Continuous Deployment (CD):**
    *   **CI:** Code is built and tested before merging to the main branch; artifacts are created for staging and production.
    *   **CD (Delivery):** Build is prepared for release but requires human approval or a planned step before production deployment.
    *   **CD (Deployment):** Build is directly deployed to production without human intervention after readiness checks.
